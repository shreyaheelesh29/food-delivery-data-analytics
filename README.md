## 1. Dataset

Synthetic but realistic data (seeded, fully reproducible) generated by
`generate_data.py`:

| File | Rows | Description |
|------|------|-------------|
| `data/customers.csv` | 5,000 | customer id, zone (12 Bengaluru-style zones), signup date |
| `data/restaurants.csv` | 800 | restaurant id, zone, cuisines, rating, price for two, prep time, lat/lon |
| `data/orders.csv` | 50,000 | order id, customer, restaurant, date, hour, cuisine, order value, delivery fee, discount, promo code, distance, traffic condition, driver id, delivery time, rating, weather, status |

The generator **plants real patterns** for the analysis to discover:
weekend uplift, December festive bump, lunch (12–14) & dinner (19–22) peaks,
distance/peak-hour/rain effects on delivery time, and rating sensitivity to
delivery time.

> To use a real Kaggle dataset (e.g., Swiggy/Zomato orders), drop the CSV in
> `data/` and adapt `analysis.py::load_data` — every downstream metric reuses
> the same functions.

## 2. How to run

**Or use the hosted version:** [fooddelivery-data-analytics.streamlit.app](https://fooddelivery-data-analytics.streamlit.app/)

```bash
pip install -r requirements.txt

python generate_data.py     # optional — data/ already contains the CSVs
python analysis.py          # console report of all metrics
python modeling.py          # train models, print metrics & importances
streamlit run dashboard.py  # interactive dashboard → http://localhost:8501
```

## 4. Dashboard tabs

1. **📈 Overview** — KPI cards, monthly orders/revenue trend, weekday demand, delivery-time & rating distributions
2. **🍽️ Cuisines** — top cuisines by orders/revenue, cuisine share, quality map (rating vs delivery time)
3. **🏪 Restaurants** — 15 busiest restaurants, orders vs rating bubble chart, detail table
4. **📍 Locations** — demand by zone, interactive restaurant map, zone summary
5. **⏰ Peak Hours** — hourly demand + delivery time overlay with peaks shaded, weekday × hour heatmap
6. **🚚 Delivery & Rating Factors** — delivery time vs distance (OLS trend), rating boxplots by time bin, weather/traffic impact, full correlation matrix
7. **🤖 What-If (ML)** — Random Forest what-if simulator (predict delivery time & rating from sliders), sensitivity curves, model metrics and feature importances

Sidebar filters: date range, zone, cuisine, promo code, hour range, order status.

## 5. Key findings (full-year 2024, 50K orders)

**Scale**
- 50,000 orders · ₹94.5 lakh revenue · avg order ₹189 · 6.1% cancellation rate
- Avg delivery 40.4 min · avg rating 3.01★

**Popular cuisines & busiest restaurants**
- Top cuisines by orders: North Indian, South Indian, Chinese, Biryani (≈ 51% of all orders)
- Busiest restaurant handled 89 orders/yr; the top 15 are spread across 9 zones — demand is broad, not concentrated in one area

**High-demand locations**
- Koramangala (6.9K orders) and Indiranagar (6.7K) lead; Yelahanka is smallest (1.8K)
- Central zones are faster & better rated (Koramangala 35 min / 3.26★) than peripheral ones (Yelahanka 50 min / 2.66★)

**Peak hours**
- Twin peaks: lunch 12–14 h and dinner 19–22 h (dinner is the largest, 20:00 = 5.6K orders)
- Weekends run ~34% busier than weekdays; December ~25% above average

**Factors affecting delivery time**
- **Distance is dominant** — correlation r ≈ 0.81; 0–2 km orders avg 29 min vs 73 min for 10+ km
- **Peak hours add ~9 min** (43–44 min vs ~35 off-peak) — kitchen queueing + traffic
- **Heavy traffic adds ~4 min** (traffic condition field); weekends add ~3.5 min
- **Rain adds ~9 min** (47.5 vs 38.8 min)
- Order value has no effect (r ≈ −0.02)

**Factors affecting rating**
- **Delivery time is the strongest driver** — r ≈ −0.69; ratings collapse from 4.0★ (<25 min) to 1.4★ (>60 min)
- Rain cuts ratings by ~0.7★ (2.38 vs 3.15)
- Distance correlates with rating at r ≈ −0.53, but this is mediated by delivery time — slow logistics, not food quality, drives low scores in peripheral zones

**Business implications**
1. Position/incentive riders near hot zones before 12:00 and 19:00 surges
2. Cap promise times by distance band rather than a flat SLA
3. Rain-mode pricing and rider bonuses to protect both speed and ratings
4. Peripheral expansion (Yelahanka, Electronic City) needs its own rider fleet — the rating gap is a logistics problem

**Predictive models** (see `modeling.py`, delivered orders, 80/20 split)

| Model | Best estimator | MAE | R² |
|---|---|---|---|
| Delivery time | Random Forest (200 trees) | **1.39 min** | 0.987 |
| Rating | Random Forest | 0.61★ | 0.52 |

- Delivery-time model beats the mean-baseline by ~9× (baseline MAE 12.4 min)
- Feature importances confirm the EDA: distance (0.69) + prep time (0.16) + hour (0.08) drive delivery time; **delivery time itself (0.77) drives ratings**
- Linear regression benchmarks included for comparison (delivery: R² 0.919, MAE 3.6 min)
- What-if example: the same 2 km Biryani order takes **22 min** on a quiet weekday afternoon, **29 min** at the heavy-traffic dinner peak, and **82 min** for an 11 km rainy haul
